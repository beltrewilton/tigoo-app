# Sign the DGII application XML

`TigooServer.Sign` supports the `Postulacion` document generated by DGII's portal.
It uses the existing enveloped RSA-SHA256 XMLDSig implementation with the supplied
PKCS#12 certificate, and verifies the generated signature before returning it.
This does not verify the applicant's registration or representative authorization;
use the certificate of the representative named in the application.

From `server`, with the updated signer already compiled:

```bash
bash sh/sign_fe_postulacion.sh ans ../fe/202610253240465.xml
```

The script loads `.env`, reads the single `.p12` in `p12_companies/ans/` and its
password from `credentials.txt`, and creates:

```text
fe/202610253240465.signed.xml
```

For production, select its environment and tenant explicitly:

```bash
MIX_ENV=prod ENV_FILE=.env-prod bash sh/sign_fe_postulacion.sh evofitdb ../fe/202610253240465.xml
```

An optional third argument selects another output path. XML paths are relative
to `server`, or absolute. The script refuses to overwrite existing output files.
It uses `mix run --no-compile --no-start`: it does not compile the application,
start Phoenix, connect to the database, or call any HTTP endpoint. It only creates
the signed output and temporary signing files, which the signer cleans up.

In DGII's portal, choose the resulting `.signed.xml` using **Elegir archivo**,
then **ENVIAR ARCHIVO**. Do not format or modify the file after signing it.
The script does not upload anything automatically or alter the source XML.
